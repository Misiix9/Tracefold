# Tracefold 0.2.1 Beta

A plugin browser, plugins that run inside the application, and updates that find and stage
themselves without being asked.

## Plugin browser

The Plugins page now has **Browse** alongside **Installed**. It lists plugins from a public
catalog with search, categories, publisher, size, and the capabilities a plugin declares —
shown before you install it, not after. Plugins you already have are marked, and a newer
version shows as an update.

Every package is downloaded over HTTPS and checked against the SHA-256 recorded in the
catalog before a single byte reaches plugin storage. A package that does not match is
discarded, not installed. The package's own manifest must also declare the same id and
version as the catalog entry that advertised it.

**Install from file** is unchanged and still available for packages you reviewed yourself.

The catalog address is configurable through host configuration, so a team can point
Tracefold at its own reviewed catalog without waiting for an application release.

## Plugins run inside Tracefold

A plugin now opens **inside the Tracefold window** instead of only in a separate window, and
a running plugin gets its own button in the sidebar. Tracefold tells the plugin which theme
and language you are using, so a plugin can match the rest of the application. Opening a
plugin in a separate window is still available.

## Tracefold Discovery

Discovery ships as the first catalog plugin: authenticated website and API discovery with
multi-user authorization testing.

- Runs inside the Tracefold window and follows the Tracefold theme.
- Opens Chromium only where a browser is genuinely required — headed for an interactive
  login you complete yourself, headless in the background for authenticated crawling.
- Keeps accounts, encrypted sessions, test cases, scans and reports in its own persistent
  directory, so updating the plugin never touches them.
- Saves reports to disk and offers to show them in your file manager.

The first launch prepares Discovery's private Python environment and its own Chromium build,
showing progress inside the Tracefold window. This happens once and is kept across updates.
Discovery needs Python 3.11 or newer available as `python3`, `python` or `py`; on Debian and
Ubuntu, `python3-venv` is also required.

## Updates that look after themselves

Tracefold keeps itself current. **Install updates automatically** is on by default: a new
version installs when you next open Tracefold, and while you are working it asks first
rather than restarting under you.

A dialog shows what is happening while an update applies — downloading, saving your work
and backing up projects, installing, restarting — so it is never a mystery why the app is
busy.

Checks run every minute by default, and finding nothing new is nearly free: Tracefold asks
the release feed only whether it changed, which an unchanged feed answers with an empty
`304`. The interval is adjustable in Settings from every minute to once a day.

**Keep plugins up to date automatically** does the same for installed plugins, and each
plugin also shows a one-click **Update** on the Plugins page. A running plugin is never
replaced underneath you — it updates once it is idle.

### Details

Tracefold now checks for a newer version on its own — shortly after opening, every hour
while running, and when you return to the window — and backs off quietly when the feed is
unreachable. You no longer have to press **Check for updates** for one to be found.

A found update **downloads in the background** while you keep working. Nothing is
interrupted, no progress window appears, and nothing is installed. When it is ready, the
sidebar offers **Restart to update**, which applies it immediately.

On Windows the update installs silently: no installer window, no interaction, no
administrator prompt. macOS and Linux replace the application in place as before.

Saving and backing up now happen immediately before installation rather than before the
download, so the recovery snapshot covers everything written while the download was running.
A failure to save or back up still prevents installation.

## Fixed

- **Installing a plugin from a file failed in 0.2.0.** The capability allowlist still
  permitted a command that had been replaced, so the installer was unreachable in packaged
  builds. A test now keeps the allowlist and the registered commands in sync.
- Plugin manifests may list fallback runtime commands, so a package needing `python` still
  starts on a machine where the interpreter is only `python3` or `py`.
- A 256 MiB plugin package no longer crosses the application's internal message boundary:
  extraction happens natively, reusing the same path validation, size limits, manifest
  checks and atomic replacement as before.

## Also in this release

- Interactive browser login in Discovery now verifies TLS certificates. Accepting an
  untrusted certificate is an explicit per-account choice rather than the default.
- Changing an account's authentication mode no longer leaves the previous mode's
  credential in use. A bearer account authenticates with its token; interactive and form
  accounts authenticate with the session they captured.
- If Discovery's Chromium download fails, reopening the plugin retries it instead of
  remembering the failed attempt as complete.
- Two reports saved in the same second no longer collide.
- The plugin catalog address is host configuration (`TRACEFOLD_PLUGIN_CATALOG`, or a
  `catalog-source` file in Tracefold's plugin storage) and is never taken from the
  application window.

## Known limitations

- Plugins remain **trusted local code**. They run as your operating-system user and are not
  sandboxed by Tracefold. Declared capabilities are shown for transparency; they are not an
  enforced permission boundary. Only install plugins you trust.
- Plugin packages are verified by checksum against the catalog. They are not yet signed by a
  publisher identity.
- The catalog has no ratings, reviews or submission workflow yet; these are v0.8.0 items.
- Discovery is published as 2.1.0. If you previously hand-installed a build numbered above
  that, the catalog will not badge this as an update; use **Reinstall** or **Install from
  file**.
- Discovery's first launch downloads a Chromium build and can take several minutes on a slow
  connection. Without it, browser login and authenticated crawling are unavailable, though
  bearer-token discovery and test runs still work.
- Silent Windows installation, the background download path, and the first-launch plugin
  bootstrap are covered by automated tests and were exercised on Linux during development.
  Version-to-version installation on each supported platform remains a release acceptance
  check, not something these tests prove.
